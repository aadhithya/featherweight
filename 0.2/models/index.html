    Models and providers¶

    An agent's model says which model runs it and how hard it thinks. Each provider has its own class, because the controls differ: a thinking level, an effort, an on/off switch.

    from featherweight import Claude


class Triager(AgentBase):
    model: ModelSettings = Claude(model="claude-haiku-5-5", effort="low")

    The reasons and the details are in the spec. This page is how to use it.

    The providers¶

    Class Models Control Default
    Gemini gemini-3.8-flash, gemini-3.6-flash, gemini-3.5-flash-lite thinking: minimal, low, medium, high (3.8-flash has no minimal) gemini-3.5-flash-lite, medium
    Gemma gemma-4-26b-a4b-it, gemma-4-31b-it thinking: minimal (off) or high gemma-4-26b-a4b-it, minimal
    Claude claude-haiku-5-5, claude-sonnet-5-5, claude-opus-5-5, claude-fable-5-2 effort: low, medium, high, xhigh, max. thinking: adaptive, or off where allowed claude-haiku-5-5, medium
    OpenAI gpt-6-luna, gpt-6.1-terra, gpt-6.1-sol, gpt-6-astra, gpt-6.2-sol, gpt-6.2-astra effort: none, low, medium, high, xhigh, max, as each model allows gpt-6-luna, medium

    Every class also has max_output_tokens, the most the model may produce, thinking included. Claude needs it, so it defaults to 16,000 there: raise it at xhigh and max.

    Every class also has show_thoughts (default False): it asks the provider to return the model's thoughts, so that a streaming agent can show them. How hard the model thinks is the other setting. What comes back differs by provider: Claude returns a summary of its thinking (newer models return none unless asked, so Claude sends display: "summarized"), OpenAI a reasoning summary (the raw reasoning stays hidden), Gemini and Gemma their thought summaries. It is refused where there is nothing to show: Claude(thinking="off") and OpenAI(effort="none"). A class you write reads self.show_thoughts in build().

    An agent with no model uses Gemini(). Because show_thoughts is part of the settings, it is part of the agent's hash: a run recorded before it existed is no longer matched when a job is resumed.

    Install and keys¶

    Gemini and Gemma come with featherweight. The other two are extras:

    pip install 'featherweight[anthropic]'     # ANTHROPIC_API_KEY
pip install 'featherweight[openai]'        # OPENAI_API_KEY

    A package that is missing, or a key that is not set, fails the run at once with a message that says what to do, and is not retried.

    What is checked¶

    When the agent is defined:

    • the model must be one of the class's models, and the message lists them;
    • the effort must be one that that model accepts: gemini-3.8-flash has no minimal, and gpt-6.2-sol does not accept none;
    • Claude(thinking="off") is accepted only for a model that allows it (claude-haiku-5-5), and only at high effort or below;
    • show_thoughts needs a model that thinks (see above);
    • the output model must be one the model can fill (provider limits);
    • a field the class does not have is an error.
    Gemini(model="gemini-3.8-flash", thinking="minimal")
# ValidationError: gemini-3.8-flash does not accept thinking='minimal'. It accepts: low, medium, high

    No temperature¶

    None of the classes takes temperature, top_p or top_k. The current models either ignore them (Gemini 3.6), reject them with a 400 (Claude 5), or ask you to omit them (GPT-6.2), and a setting that is silently dropped hides a mistake. Claude(temperature=0) says so:

    Claude has no `temperature`: the current models of this provider refuse or ignore it, ...

    To make output more repeatable, give the agent clear rules in its prompt, use enums in the output model, and use check_output. No provider documents a switch for it. A class for a model that does accept temperature can declare the field (Ollama below).

    Add a model: GPT-5.x¶

    The built-in OpenAI class lists the GPT-6 models. To use GPT-5.5, subclass it and add the model to its catalog:

    from typing import ClassVar

from featherweight import ModelInfo, OpenAI


class OpenAI5(OpenAI):
    models: ClassVar[dict[str, ModelInfo]] = {
        **OpenAI.models,
        "gpt-5.5": ModelInfo(efforts=("none", "low", "medium", "high"), default="medium"),
    }


class Reader(AgentBase):
    model: OpenAI5 = OpenAI5(model="gpt-5.5", effort="low")

    efforts is what the model accepts. Everything else, including build(), is inherited, so the new model gets the same validation: OpenAI5(model="gpt-5.5", effort="max") is an error, and so is OpenAI(model="gpt-5.5"), because the built-in class is unchanged.

    Check what the older model needs. GPT-5 models, for instance, refuse a temperature other than 1 unless the effort is none. If you want a field, add it to the subclass and override build().

    Add a provider: Ollama¶

    Any provider that LangChain has a chat model for works. Write a subclass with its fields, and build():

    from typing import ClassVar

from pydantic import Field

from featherweight import ModelSettings


class Ollama(ModelSettings):
    provider: ClassVar[str] = "ollama"
    temperature: float | None = Field(default=None, ge=0, le=1)  # its own field, so it is accepted
    reasoning: bool | None = None

    def build(self):
        from langchain_ollama import ChatOllama  # imported here, so `featherweight` does not need it

        return ChatOllama(model=self.model, temperature=self.temperature, reasoning=self.reasoning)


class Local(AgentBase):
    model: ModelSettings = Ollama(model="gpt-oss:20b", temperature=0.2)
    • build() is required. It is the only method you must write, and it returns the LangChain chat model. The base class does not provide one: if you leave it out, the class can still be created and put on an agent, but the first run fails with NotImplementedError: <Class> must write build(). A setup error is not retried, so the run fails at once. The runner calls agent.model.build() for every attempt.
    • With no models catalog, any model name is accepted and efforts are not checked. Add a models catalog, and an effort_field naming the field that holds the effort, to get the checks of the built-in classes.
    • label() is the short text the run log keeps. It is the effort field by default, and can be overridden.
    • Raise SetupError (from featherweight.errors) for a problem that a retry cannot fix. require("langchain_ollama", "ollama") imports a package and raises one that names the install command.

    Ollama's tool support depends on the model you pull, and its docs list token usage as unsupported, so check what your model reports.

    Testing your agents¶

    The runner has no argument for choosing a model: an agent's own model settings decide it, and the runner calls agent.model.build(). So a fake is model settings too. Write a settings class whose build() returns a fake chat model, and run the agent with it:

    from typing import Any, ClassVar

from pydantic import Field

from featherweight import ModelSettings


class FakeSettings(ModelSettings):
    provider: ClassVar[str] = "fake"
    model: str = "fake-model"
    chat: Any = Field(default=None, exclude=True)  # the fake chat model; not part of the settings' data

    def build(self):
        return self.chat


fake = ...  # a chat model that replays a script


class UnderTest(PeopleExtractor):  # the same agent, run by the fake
    model: ModelSettings = Field(default_factory=lambda: FakeSettings(chat=fake))


result = await AgentRunner(db).run(UnderTest, ExtractInput(text="..."))

    Nothing in the runner exists for tests, so the test runs the same code as production. The recipes have a whole test file with a fake chat model.

    Tokens and the run log¶

    input_tokens and output_tokens on the result mean the same for every provider: all input, and all output with thinking. The runner sums them over the model calls of the successful attempt.

    The run log has one row for each attempt. For the model it keeps:

    Column
    model_name, reasoning The model, and the effort or thinking level as text
    reported_model_name What the API reported
    provider google, anthropic, openai, or your class's provider
    settings All the settings as JSON, so a run can be reproduced

    Rows written before these columns have NULL in provider and settings.

    Provider limits¶

    How a provider is asked for typed output differs by model, and each way has limits. They come from Anthropic's API and SDK, and from LangChain, which featherweight builds on. featherweight does not work around them. It refuses what would go wrong, and says why.

    Warning

    Claude Opus, Sonnet and Fable do not take every output model. An agent with one of these is refused when it is built:

    • No dictionaries. A dict of any kind (also in a list, or optional), and a model with extra="allow". Anthropic's SDK sends it as an object that may hold nothing: the field would always come back empty, and the run would succeed.
    • No recursive models, such as a tree whose nodes hold nodes. The API refuses the request.
    • At most 24 optional fields, counted over the model and the models inside it. open_questions is one of them, so a flat output has room for 23 of your own. A field with a default is optional.

    Use a list of a small model in place of a dictionary:

    class Entry(BaseModel):
    key: str
    value: str


class Out(AgentOutput):
    entries: list[Entry] = []  # not `dict[str, str]`

    Warning

    A model can answer before it has seen what its tools returned. For Claude Haiku 5.5, the default Claude model, the typed output is one more tool. The model can call it in the same reply as your tools. LangChain then takes that answer, runs your tools and ends, so the answer is empty or made up.

    featherweight fails that attempt (EarlyAnswerError) and retries it, like any failed attempt. Your tools have run by then, and run again on the retry: a tool that sends or writes something must be safe to run twice. With max_attempts=1, the run is FAILED.

    Warning

    A reply that does not fit the schema is not always sent back to the model. Where the output is a tool call (Haiku), LangChain returns the error to the model within the same attempt. With a provider's structured output (Claude Opus, Sonnet and Fable, and OpenAI), the attempt fails and is retried. Claude is not given numeric or length limits (ge, max_length) as rules, only as text in a description, so a reply can break them.

    The schema is checked by a method of the model settings, check_model_output_schema, so a settings class of your own can add its provider's limits. The early answer is checked by the runner, for every model. The decisions, and what was seen on the real APIs, are in the specs of models and the runner.

    Limits¶

    • Gemma and tools. With tools and an output model in one agent, both hosted Gemma models answered in JSON at once and did not call the tool, where Gemini did. Prefer Gemma for agents without tools.
    • Claude's bounds. The API does not enforce numeric bounds in an output model (ge, le), so use check_output.
    • Typed output differs by model: see provider limits before you choose a Claude model.
    • OpenAI. Tested with gpt-6-luna only. Every OpenAI model here uses the Responses API.
    • Older models (Gemini 2.x, Claude 4, GPT-5) are not built in. Add them as above.
    • Not available: token budgets (thinking_budget, budget_tokens), verbosity, reasoning.mode: pro, a different model on a retry, and a cost report. A subclass can add the fields it needs.
